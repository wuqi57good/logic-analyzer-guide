CHAPTER 00 / 12

0. 阅读指南：先找到你的学习路线

约 8 分钟起步上机 + 仿真双路线

你不需要先背下一整页术语。先把一个会规律翻转的引脚画出来，再让软件把高低电平翻译成字节。能解释自己看到的每一步，比一次打开所有解码器更有用。

先建立一个能用的理解

逻辑分析仪是给数字引脚拍连续快照的工具。把它想成同时盯住八扇门的值班记录员：门开写 1，门关写 0，再记下时刻。你会用这些记录判断“谁先动、谁没回应、哪一位读错了”。

先把你会在界面里遇到的四个词说成人话。采样率（Sample rate）是每秒拍多少张状态照片：照片拍得太稀，短暂发生的事会落在两张之间。存储深度（Memory depth）是相册能放多少张：相同拍照速度下，相册越大，能回看的时间越长。

触发（Trigger）是“等什么事件才定位这段记录”，像相机等运动员冲线再拍；它帮你留下关心的瞬间。协议解码（Protocol decoding）是按通信约定给高低电平加字幕，像把点划翻译成句子；配置错了，字幕也会错。你现在只需记住用途，后面会一个参数一个参数地试。

比特（bit）就是一个二进制位，只有 0 或 1，像一盏灯的灭或亮；常见的一个字节（byte）包含 8 位。小盒子外壳常把采样率写成“24 MHz”，本教程用 24 MS/s 明确表示每秒 2400 万次采样，不把它误解为“能可靠解码 24 MHz 的总线”。

这份教程有两条同样有效的路线。有机器时，边读边接自己的低压开发板；没有机器时，先完成各章交互练习，写下你预期出现的波形，再用仿真验证。真正借到设备后，只需补上接线与软件操作。

全程用 8 通道、标称 24 MHz 的常见 USB 小盒子作为外形示例。外壳相似不代表输入保护、电压耐受、门限、驱动或最高持续传输能力相同；最终以你那块板的资料、芯片和软件实际报告为准。

文中的数值都是明确标注的示例值。协议动画会把时间放慢，方便你逐位观察；其单位与事件先后关系仍有定义。高级触发、可调阈值和右侧配置展示是教学扩展，不意味着学校的小盒子真的提供这些硬件功能。

真实操作：一步一步做

  1. 准备低压开发板、USB 逻辑分析仪、合适的 USB 数据线、信号排线与测试钩、万用表。能借到示波器更好；它用于确认电平与波形质量。
  2. 把开发板原理图、芯片数据手册、引脚定义放在手边。先确定被测点是逻辑信号、参考地在哪里、最大可能电压是多少。
  3. 第一次只打开一个信号通道；确认成功后，再增加时钟、片选或另一条数据线。每次改变一个因素，记录前后结果。
  4. 读到一个新词时，先看生活类比，再做对应交互。忘记名词可查附录；不必为背定义中断练习。
  5. 遇到卡点，按“设备是否识别 → 接地与电平 → 采样与时长 → 原始波形 → 解码设置”顺序检查，保留原始采集文件。

把这一章变成你的经验

上机微练习

找出开发板的 GND、一个已知 GPIO 和供电电压。先不接逻辑分析仪，用原理图与万用表完成身份核对，在纸上画出三者的关系。验收：你能说明为何接地和确认耐压要先于点击 Run。

没有机器：仿真替代练习

按目录打开第 1、2、5 章的三个演示。依次改变“观察方式”“是否共地”“采样率”，每次只动一个控件，写下一句因果判断。验收：能指出哪个变化来自电气连接，哪个来自采样过程。

常见踩坑

  • 一口气加八个通道和三个解码器，出错后不知道该查哪里。先用一个已知信号建立可信基线。
  • 只抄解码文字，不保存波形。文字可能来自错误配置，原始采样才便于复核。
  • 把仿真的所有按钮当成实物功能。看到“教学扩展”时，先查设备能力，再选择上机替代步骤。

本章自检

  • 我知道借到的设备型号与输入限制需要单独核对。
  • 我能按自己的条件选择上机或仿真路线。
  • 我会记录设置、假设和复测结果。
没有机器，这份教程还能练什么？

可以练参数选择、波形阅读、协议逐位识别、触发条件设计和排障假设。真实接线、电压测量与驱动安装仍需之后上机完成。

为什么第一次只开一个信号通道？

变量少，容易分清设备识别、接线、采样与程序输出的问题。一个通道可信以后再扩展。

解码结果与自己的预期不一致，先相信哪个？

先查看原始波形与设置，再独立数位。预期和解码器都可能错，不能只凭某个字节好看就判定通信正常。

CHAPTER 01 / 12

1. 逻辑分析仪在测什么，又不测什么

约 12 分钟入门上机 + 仿真双路线

万用表显示 3.3 V，程序却一直收不到数据；你很容易怀疑“电压明明对，怎么还是不通”。原因是通信不仅要有电压，还要在正确时刻变成正确的高低状态。

先建立一个能用的理解

数字信号把一段电压范围解释成 0 或 1，像交通灯把连续变化的亮度归成“亮”和“灭”。逻辑分析仪保存的是这种判断随时间的变化，不是每个时刻的精确电压。

阈值是判断高低的分界线，像门口的身高线。越过线算高，低于线算低。门限不合适时，同一条真实电压曲线可能被记成不同的 0 和 1，所以解码前必须确认电平兼容。

时序是事件发生的先后与间隔，像接力赛必须在交接区交棒。数据若在接收方采样的瞬间才改变，哪怕最终电压正确，也可能被读错。

协议解码是把一串高低电平按约定翻译成地址、字节和应答，像给摩尔斯电码加字幕。字幕依赖正确的通道、位序、波特率和模式；它不能替你判断接线或信号质量。

右侧方波很漂亮，不代表板上没有过冲、振铃、慢边沿或电源噪声。数字记录可能把这些细节全部压成一个 1。遇到电平裕量或边沿形状问题，要切换示波器并检查探测方式。

工具 适合回答 容易漏掉
万用表 供电电压、通断、稳定电平是否大致正确 短脉冲、逐位内容与事件先后
示波器 电压随时间怎样变化，是否过冲、振铃、慢上升 取决于通道数、存储与解码选件，多路长记录可能不经济
逻辑分析仪 多路数字先后关系、脉宽、协议内容与较长记录 真实电压、模拟边沿形状、输入裕量

示波器也能做时序测量，许多型号带协议解码，混合信号示波器还带数字通道。逻辑分析仪的优势通常是数字通道数量、长记录和使用成本，不能说示波器做不到协议分析。

交互 02 · 同一根线，两种视角

示波器看“长什么样”，逻辑分析仪看“是 0 还是 1”

这一步在教你什么：一条看起来规整的数字波形，并不能证明它的真实电压没有过冲、振铃或缓慢边沿。两边读取的是同一组电压数据。

图中 1.65 V 是教学门限的示例值，不是你手中设备的保证参数。只要振铃没有让输入反复跨过门限，逻辑分析仪就可能一直画出干净方波。把滑块向右拖，你会看到“方波看着没事”和“电压质量很好”是两回事。

数字波形里有毛刺，是否就能知道真实电压长什么样？

也不能。它只能告诉你某些采样时刻被判成了不同逻辑值。噪声多高、振铃振了几次、上升沿到底多缓，需要示波器确认。现代示波器与混合信号示波器也可能带多路数字输入和协议解码；工具分工不是“示波器绝对做不到”。

真实操作：一步一步做

  1. 确认目标是“电压质量问题”还是“时间与内容问题”。前者优先示波器，后者适合逻辑分析仪；复杂问题两种工具配合。
  2. 在 PulseView 中选择已识别设备，启用一条 GPIO，采样率用示例值 1 MHz，抓取示例值 10 ms。
  3. 让程序每 1 ms 翻转一次引脚。预期高电平和低电平各约 1 ms，一个完整周期约 2 ms。
  4. 放大一处边沿，再缩回看几个周期。把“逻辑状态切换的时刻”和“模拟上升沿形状”区别开。
  5. 保存采集文件，并记录程序的翻转周期、采样率、时间窗口和通道。

把这一章变成你的经验

上机微练习

用定时器产生约 500 Hz 的方波。测得周期应接近 2 ms；若用软件延时，记录实测与预期的差异。再用万用表测这个点，解释为什么平均读数不能告诉你每一位发生了什么。

没有机器：仿真替代练习

在对比器中改变振铃和边沿参数。观察模拟曲线已明显变坏时，数字方波是否仍保持原样；比较器刻意把振铃控制在门限裕量内；接着到第 9 章阈值演示观察噪声越过判断线。验收：分别描述“数字看不见的恶化”和“已经造成数字误判的恶化”。

常见踩坑

  • 把逻辑 1 当成固定 3.3 V。高电平由接收器的输入规范定义，不是一切设备共有的数值。
  • 把解码成功当成信号质量合格。当前这次采样能过，不代表温度、供电或线长变化后仍可靠。
  • 仅凭数字波形判断上升沿有多快。采样率和门限共同决定了你看到的跳变位置。

本章自检

  • 我能解释为什么同一电压曲线会变成高低方波。
  • 我能为电压、时序、协议三个问题选择合适工具。
  • 我不会用解码成功代替模拟质量检查。
逻辑分析仪能测出 4.2 V 的过冲峰值吗？

通常不能。它只记录输入逻辑状态；需要带合适探头、带宽和输入保护的示波器检查峰值与持续时间。

示波器一定不能解码 I²C 吗？

不是。很多示波器有协议解码或可选功能。应按通道数、存储、模拟观测需要和预算分工。

为什么解码器输出有意义的字符，仍不能立即宣布修好了？

错误设置也可能偶然得到可读字符。还要检查帧结构、应答、重复性与修改后的持续复测。

CHAPTER 02 / 12

2. 第一次上手：把第一段波形抓出来

约 20 分钟上手上机 + 仿真双路线

第一次插上 USB，最让人头疼的往往不是波形，而是软件找不到设备。把“电脑识别”“信号接对”“采样设置”分开处理，你就不会在三个问题之间来回猜。

先建立一个能用的理解

驱动是操作系统与 USB 设备之间的翻译员。PulseView 通过 sigrok 支持的后端与设备通信；能在设备管理器里看到名字，还不等于已绑定软件所需的驱动。

WinUSB是 Windows 的通用 USB 驱动之一；Zadig是帮特定 USB 接口安装兼容驱动的小工具。像给正确的房间换门锁：一定先核对设备，别把键盘、鼠标或调试器的接口改掉。

共地是让两个设备用同一把“电压尺”的零点。逻辑分析仪测的是信号相对自身 GND 的电压；只有信号线、没有地线时，参考点漂浮，可能乱跳，也可能偶尔看着正常。

先让待测低压板断电，确认 USB 地与目标地适合直接相连，再接分析仪 GND 到目标板的 GND 测试点；随后接信号钩，检查无短路，最后给目标板上电。不要把保护地、未知电位或高压参考点当作安全 GND。

常见小盒子通常没有独立的 Run 实体按键；开始与停止在电脑软件完成。USB 口负责数据与设备供电，D0–D7 是输入，GND 是参考端。丝印方向以实物为准，不按排线颜色猜。

只测已确认安全的低压数字电路。绝不把这种 USB 小盒子直接接市电、高压或未知电位。绝不把 5 V 信号直接接入仅允许 3.3 V 的输入；先用合适电平转换器，或在满足带宽、保护与输入阻抗条件时采用经过计算和验证的分压。

交互 05 · 给测量一个共同的零点

接一根信号线，还差一根 GND

这一步在教你什么：分析仪判断的是“信号相对它自己地线的电压”。两边没有共地，就像两个人用不同海拔当作零点，报出的高度无法直接比较。

  1. 先让目标板处于适合接线的安全状态，确认它是允许测量的低压电路。
  2. 按实物丝印找到 GND，先连分析仪 GND 与目标板 GND；不要把电源正极当作地。
  3. 按住测试钩尾部，让小钩伸出；只勾住一个裸露测试点或排针，松开后检查金属钩没有搭到邻针。
  4. 再连接信号通道，并核对实物通道号与软件 D0 / D1 的映射。先从低速、单路信号验证，再增加通道。

绝不连接市电、高压节点或未经确认的浮地系统。USB 分析仪的 GND 往往通过电脑与其他设备相连；共地前要确认没有危险电位差。输入电压须在该设备规格允许范围内，5 V 信号不能直接接到仅支持 3.3 V 的输入。

没接地也偶尔能解码，是不是可以不接？

不能据此省掉地线。USB、电源、串口线或人体电容可能偶然提供了返回路径；换一台电脑或移动线缆，波形就可能改变。本图用确定性的干扰模型展示一种失败情形，真实未共地电压并非一定按这张图跳动，也可能看起来稳定却不可靠。

真实操作：一步一步做

  1. 从 sigrok 官方页面获取适合操作系统的 PulseView。安装后先使用 Demo device 检查界面和波形操作，再连接实物。
  2. Windows 若设备不能打开，查看设备管理器。使用 Zadig 时可打开 Options → List All Devices，核对名称、USB 标识和拔插前后的对应关系；仅为目标设备的正确接口安装所需驱动。WinUSB 是常用选择，实际依设备与后端要求。

3. 三个参数：采样率、深度与阈值

约 15 分钟入门上机 + 仿真双路线

同一块板，别人能解码，你这里却时好时坏。先别急着改程序：采样太稀、记录太短或电平判断不兼容，都会让“看到的事实”先出问题。

先建立一个能用的理解

采样率表示每秒记录多少次输入状态，像每秒拍多少张照片。示例 1 MS/s 即每秒一百万次，采样间隔为 1 μs；示例 24 MS/s 的间隔约 41.7 ns。漏在两张照片之间的窄脉冲，事后放大也找不回来。

存储深度表示能保存多少个采样时刻，像相册能装多少张照片。这里用“每通道的逻辑采样时刻数”计算时长；实际文件字节数还取决于通道打包、格式与压缩，不能把 Samples 直接当 Bytes。

抓取时长是这本相册覆盖的时间：可用时长 = 存储深度 ÷ 采样率。示例 1 MSamples ÷ 10 MS/s = 0.1 s；同样深度提高采样率，细节更多，能看的时间更短。

对有规律的数字时钟，先用最高相关频率的 5–10 倍采样作为实用起点，再按最窄脉冲与解码器要求增加。它不是可靠解码的保证，也不能保证抓住任意毛刺；若要看 50 ns 毛刺，就必须单独考虑采样间隔和硬件带宽。

VIH是接收器保证识别为高电平的最低输入电压，VIL是保证识别为低电平的最高输入电压。把它们想成一条有缓冲区的入场规则：中间地带不保证判定结果，不能当作另一个稳定逻辑状态。

CMOS（互补金属氧化物半导体逻辑）与TTL（晶体管-晶体管逻辑）是不同的逻辑电路家族，门限规范并不相同。CMOS 常见示例约为 VIL≤0.3VDD、VIH≥0.7VDD；经典 TTL 示例为 VIL≤0.8 V、VIH≥2.0 V。这些只用于理解，真正接线按各器件数据手册。

4. 触发：只等你关心的那一刻

约 15 分钟基础上机 + 仿真双路线

你点 Run，通信故障却发生在几秒以后；或者你反应过来时，关键瞬间早已过去。触发就是给记录员一条“什么时候值得拍”的规则，像相机等到人走进画面再按快门。

先建立一个能用的理解

边沿触发等信号由低到高或由高到低，适合找复位、片选、起始位。脉宽触发等某个高或低持续超过或短于设定时间，适合抓过窄的脉冲。

总线值触发等解释后的地址或数据出现，像听到车牌号再按快门。序列触发要求事件按顺序发生；超时触发要求某状态或事件间隔超出限制。这些通常需要更强的硬件或特定软件支持。

本教程把五种条件做成教学仿真。常见 FX2 设备在 sigrok 中通常只有有限的触发支持，实际能力由设备驱动决定；不要假定 PulseView 能直接设“I²C 地址 = 0x68”或多级序列条件。

前置采样是保存触发之前的一段记录，像行车记录仪保留事故前几秒。它能回答“错误之前谁先异常”。是否有预触发、可设比例与实现方式，要看设备和软件；本仿真允许观察这种概念。

Single表示满足条件后完成一次采集并停住；重复采集则会继续等待下一轮。这里是采集行为的解释，PulseView 的按钮名称与可用模式按版本和设备而定，不能把其他软件的按钮名称直接套过来。

这一步在教你什么：先定义“什么事件值得抓”，再保留事件前后。以下五种条件都在同一条数据记录上搜索；条件匹配之前，窗口不会提前显示命中。

这五种能力是教学仿真。基础 FX2 兼容款和 PulseView 不能被假定支持协议、脉宽、多级序列、超时或预触发。实机可用固件标记 GPIO 配合边沿触发，或长记录后筛选；需要实时高级触发时应换用明确支持的仪器。

    示例数据：先出现对 0x48 的正常写入，再对 0x68 写 0xEE；随后一个 120 ns 脉冲、一个故障标记和一段 SCL 长低电平。地址与序列条件从采样的 SDA/SCL 解码；毛刺条件从样本边沿量出，不按按钮硬切提示。

    为什么脉宽触发的时间标记在脉冲结束处？

    只有脉冲结束后，触发器才知道它有多短。长脉宽/超时条件则可以在计时达到门限时成立。前置记录能把原因留在事件标记之前；记录比例改变的是窗口，不会把物理事件搬到别处。

    为何地址 0x68 命中了，还不一定抓到通信错误？

    访问某地址是普通事件，不等同于错误。你可以用它缩小记录范围，再检查后续字节、ACK 和超时。序列与超时条件更具体，但也要避免设得太严而永远等不到。抓到之后先看原始波形，再相信解码文字。

    真实操作：一步一步做

    1. 先用一句话定义事件，例如“片选拉低后，预期 1 ms 内没有返回完成信号”。能讲清事件，才能选触发。
    2. 在 PulseView 点击对应通道名，检查设备实际提供的触发选项；为示例 CS 通道选下降沿。没有相应选项时使用替代方案。
    3. 把记录窗口设得足以覆盖事件前后的上下文。若设备支持预触发，留一部分数据观察原因；不支持时提前开始记录。
    4. 开始等待后再执行一次目标操作。采集完成立即检查触发标记与波形，不要反复覆盖唯一的故障记录。
    5. 保存这次原始数据；相同条件重新采集一次，确认触发的是同一类事件。

    5. 波形区：缩放、游标与时间测量

    约 15 分钟基础上机 + 仿真双路线

    满屏高低线像一团草稿，放大以后又找不到原来的位置。把操作拆成“找整段 → 找一帧 → 找一位 → 放光标”，你就能从全局走到证据。

    先建立一个能用的理解

    时间轴是波形的横向尺子，向右表示时间变晚。放大只改变显示尺度，不会补回没有采到的数据；把模糊照片放大，细节不会凭空出现。

    光标 A/B是可以移动的两根时间标记，像尺子的两个端点。它们的差值 Δt 用来测脉宽、周期、延迟；若 Δt 是一整周期，频率 f = 1/Δt。

    位时间是一个数据位占据的时间。UART 示例 115200 bit/s 的位时间约 8.68 μs。测相邻边沿时要确认中间没有连续相同位；否则测到的是几个位时间的总和。

    这里的主控台按 PulseView 的工具栏、左侧通道区、中央时间轴与解码行组织。右侧是把实际弹出配置展开后的教学面板；真实 PulseView 通道和解码器设置常通过点击行名打开，并没有统一固定右侧 Inspector。

    【Logic 2 不同】Saleae Logic 2 常通过右侧侧栏管理 Analyzers，并在 Capture Settings 中配置采集和触发；PulseView 的工具栏、通道弹出项和解码行组织方式不同。兼容小盒子也不代表可以运行 Saleae 官方软件。

    数字时间测量有采样量化误差。示例 1 MS/s 的一个采样间隔是 1 μs，两个边沿分别落在采样格附近时，不能把显示出的很多小数位当作同等精度。用更高采样率和重复测量验证关键时序。

    6. I²C：读懂一次完整的对话

    约 25 分钟实战上机 + 仿真双路线

    I²C 驱动返回错误，只知道“传感器不理我”。把每次事务拆成起始、地址、应答和数据，就能定位它到底在哪一步没有按约定行动。

    先建立一个能用的理解

    I²C（集成电路间总线）是两根通信线共用的一套总线约定：SCL 是时钟，像老师打拍子；SDA 是数据，像学生在指定拍点展示答案。再加一根 GND 给测量建立共同参考。

    开漏意味着器件主要负责把线拉低，高电平由上拉电阻把线拉向电源。像多人拉同一根绳子，任何一人拉低都会低，没人拉时才回高；没有合适上拉，线不能可靠回到高电平。

    START 是 SCL 为高时 SDA 从高变低；STOP 是 SCL 为高时 SDA 从低变高。普通数据位期间，SDA 应在 SCL 为高时保持稳定，通常在 SCL 低电平期间改变。

    标准 7 位地址事务的首字节是 7 位地址加 1 位方向：0 表示写，1 表示读。例如地址 0x68 的线上传输首字节是写 0xD0、读 0xD1；不要把 7 位地址和含方向位的 8 位表示混用。

    ACK是接收方在第九个时钟把 SDA 拉低，表示应答；NACK是该拍保持高。像收件人签收或拒收。读事务的最后一个字节通常由主机发 NACK，表示“我读完了”，这不是从机失联。

    时钟拉伸是目标器件暂时把 SCL 保持为低，像说“等我一下”。逻辑分析仪能看见低电平变长，但不能仅凭这条线证明是谁拉低；结合主机行为、器件规范和必要的模拟测量判断。

    教学动画使用写事务：START → 地址 0x68 + W → ACK → 寄存器 0x2C → ACK → 数据 0xA5 → ACK → STOP。寄存器与字节均为示例值，不是某款传感器的真实命令。读寄存器经常需要先写寄存器指针，再重复 START 改为读，具体按器件数据手册。

    故障情景 数字记录里的线索 下一步
    地址无 ACK 第九个 SCL 高电平期间 SDA 仍高 核对地址、供电、复位、接线与就绪时间
    时钟拉伸 SCL 低电平显著延长 核对目标是否允许拉伸、主机超时与驱动支持
    上拉过大 / 电容过大 上升过晚、有效高电平缩短或解码异常 用示波器测上升沿，再按总线电容与下拉电流选阻值
    交互 06 · 把一笔通信拆成每一位

    I²C：跟着时钟，读完一次寄存器写入

    这一步在教你什么：沿着 SCL 的上升沿读取 SDA，把电平还原为地址、应答与数据。先看正常帧，再一次只加入一种故障。

    SCL：时钟，告诉你什么时候读 SDA：数据，告诉你读到 0 还是 1 圆点：实际采样值；竖带：当前步骤

    教学模型的示例值：100 kHz 时钟、7 位地址 0x68、寄存器 0x2C、数据 0xA5。线上地址字节是 0xD0 = (0x68 << 1) | 0，最低位 0 表示写。地址解码由 SDA/SCL 边沿得到；I²C 解码器通常不需要你另填波特率。

    为什么这里是三个 ACK，而读操作最后常出现 NACK？

    这里演示的是主机向从机写数据：地址、寄存器、数据的第九个时钟都由接收方拉低 SDA 表示 ACK。读数据时，接收方变成主机；主机读完最后一个字节通常发 NACK，告诉从机“我不再继续读了”，随后 STOP。这是正常结束，不能一看到 NACK 就判故障。

    慢上升沿是怎样变成错误解码的？

    本模型保留理想 SCL，只让 SDA 按 RC 充电曲线上升，数字门限为 1.65 V、时间常数为 9 μs，都是示例值。SDA 来不及在 SCL 上升前越过门限，读到的 1 会变成 0；它随后又可能在 SCL 为高时越过门限，被误认成 STOP。真实电路还要同时检查 SCL 上升时间，具体限制应查总线速率对应的规范。

    真实操作：一步一步做

    1. 在低压板断电时，将分析仪 D0 接 SDA、D1 接 SCL、GND 接总线地；确认上拉接到与全部器件兼容的电源。
    2. 示例 100 kHz I²C 可先用示例 1–2 MS/s 观察协议；若要检查更窄的异常，继续提高采样率并用示波器确认模拟边沿。
    3. 在 PulseView 添加 I²C 解码器，把 SCL/SDA 对应到实际通道。地址从采样数据解析，普通 I²C 解码不需要手工设置“波特率”。
    4. 检查解码器显示地址的格式，区分 7 位地址与地址加方向位。时钟频率用光标测量或合适的时序显示核对，而非假定解码器要求输入。
    5. 找到 START，顺着八个数据位和第九个应答位逐位核对，再看 STOP 或重复 START。遇到读事务，确认最后一次 NACK 是否由主机主动结束。
    6. 保存成功与失败各一段，比较首次分叉的事件；不要只截最后的错误提示。

    7 位地址 0x68 的写方向首字节是什么？

    0xD0：将地址左移一位，再把方向位设为 0。读方向对应 0xD1。

    每个 ACK 都由从机发送吗？

    不是。ACK 由当前字节的接收方发送；读数据时主机是接收方，可应答继续读取，并在最后一个字节后发 NACK。

    不一定。可能是合法时钟拉伸、主机延迟或线路被拉住。要结合器件时序、主机实现与上下文判断。

    7. SPI：找准时钟的采样边沿

    约 20 分钟实战上机 + 仿真双路线

    SPI 解码已经出现字节，却和芯片手册完全对不上。最常见的陷阱是：你选对了线，却在错误的时钟边沿读取，或者根本没把完整的片选窗口圈出来。

    先建立一个能用的理解

    SPI（串行外设接口）通常用 SCLK、MOSI、MISO、CS 四根信号线，另加测量参考地。SCLK 是节拍，MOSI 是主机发给从机，MISO 是从机发给主机，CS 是“现在轮到你”的片选。方向名称以主机为参考。

    CPOL是时钟空闲电平，像休息时鼓槌停在哪边；CPHA是用第一个还是第二个有效边沿采样，像跟着第一拍还是第二拍读答案。两者组成四种常见模式。

    CPHA = 0 在第一个边沿采样、第二个边沿更新；CPHA = 1 在第一个边沿更新、第二个边沿采样。第一个边沿是离开空闲电平的边沿；因此 CPOL 会决定它是上升还是下降。

    位序是一个字节先发最高位还是最低位，像从左或从右读一排数字。MSB first 先发最高位，LSB first 先发最低位；位宽、片选极性和命令格式都必须按器件手册。

    同一条固定波形用错误模式解码可能错位、读到过渡区，甚至偶然仍相同；四种模式不保证产生四个不同字节。若发送端与接收端一起正确切换模式，同一数据应得到相同内容，只是采样边沿位置不同。

    全 0xFF 表示被解码为一串高电平。原因可能是 MISO 没驱动、CS 未正确选中、线路上拉、接错通道，也可能与时序或模式设置有关；不能看到 FF 就直接判定 CPHA 错。

    模式 CPOL / CPHA 采样边沿 更新边沿
    Mode 0 0 / 0 上升沿 下降沿
    Mode 1 0 / 1 下降沿 上升沿
    Mode 2 1 / 0 下降沿 上升沿
    Mode 3 1 / 1 上升沿 下降沿

    同一采样边沿不等于同一完整模式。Mode 0 与 Mode 3 的空闲电平和第一位准备时机不同；Mode 1 与 Mode 2 也一样。先定位片选与第一个时钟，再读数据。

    交互 07 · 找准该读数据的那个边沿

    SPI：四种模式，盯住采样点

    这一步在教你什么：同一段物理传输，解码配置一变，采样圆点和字节就可能改变。读模式前先看空闲时钟电平，再看数据在哪个边沿切换。

    CS：低时选中从机 SCK：时钟 MOSI：主机发 MISO：从机回

    物理发送端固定为 Mode 0、高位先发、CS 低有效；示例回传字节为 0x96、0x3C。改上面的模式只改变解码器，不会替你改硬件。模式对照：0 取上升沿、1 取下降沿、2 取下降沿、3 取上升沿；CPOL 决定哪个是第一个有效边沿。

    为什么 Mode 0 和 Mode 3 有时读出一样的字节？

    它们都可能在上升沿取样；同一段稳定、完整的时钟串可以出现相同结果。Mode 3 对空闲电平和第一位准备时机的要求仍与 Mode 0 不同，所以“解出一样”不能证明配置正确。本例会同时提示空闲电平不匹配。

    在数据切换的边沿采样，实际结果取决于器件延时、探头偏斜和采样分辨率。本模型明确使用边沿后 0.10 μs 的采样孔径，而数据在下降沿后 0.06 μs 切换，因而错误模式读到下一位。它展示一种可复现的移位错误，不宣称所有硬件都会得到同一个错误字节。

    全是 0xFF，能直接断定模式错了吗？

    不能。选择“从机未响应，线路被上拉”，你会看到 MISO 始终为高，任何采样点都会读到 1。检查 CS 是否选中、从机是否供电、MISO 是否接对、命令与等待时序是否正确，再核对 CPOL/CPHA。模式错误经常造成错位或不稳定字节，并不必然得到 0xFF。

    真实操作：一步一步做

    1. 断电连接 SCLK、MOSI、MISO、CS 与 GND，给通道改成明确名称，避免把 TX/RX 等其他接口标签套到 SPI 上。
    2. 查芯片允许的模式、最大时钟、位宽、位序和 CS 建立/保持时间。先用较低的示例时钟验证链路。
    3. 在 PulseView 添加 SPI 解码器，映射 CLK、MOSI、MISO、CS，并按实际提供的选项设置 CPOL、CPHA、位序、字长和片选极性。
    4. 先看原始 CS 是否在完整命令与响应期间保持有效，再检查时钟空闲电平。必要时用光标检查 CS 到第一时钟的间隔。
    5. 放大第一字节，按所选采样边沿逐位数出字节，再与解码结果比较。Flash 读命令经常有地址或 dummy cycles，按手册找到真正的返回数据。
    6. 逐次更正一个设置，并保存前后波形。不能只改解码器直到出现“看着顺眼”的字节。

    • 只连 MOSI 与时钟就期待看到 Flash 回答。返回数据通常在 MISO，且要核对命令阶段与读取阶段。
    • CS 在命令后短暂释放，芯片把下一段当作新命令。必须按芯片时序把事务分段。
    • 将解码器的模式修改误认为已经修改了 MCU 外设配置。解码配置只改变解释方式。

    • 我确认了 CS 窗口、位序与字长。
    • 我不会把所有 0xFF 都归结为模式错误。
    Mode 2 在哪个边沿采样？

    CPOL = 1、CPHA = 0，时钟空闲为高，第一个有效边沿是下降沿，因此在下降沿采样。

    四种模式解同一采集，一定得到四个不同字节吗？

    不一定。数据内容、边沿前后的稳定程度与解码器实现会影响结果，有些模式可能偶然一致。

    MISO 始终高而 MOSI 正常，应先查什么？

    先查 MISO 接线、CS 是否选中器件、器件供电/复位、命令是否有效，以及返回阶段是否找对，再检查模式和时序。

    8. UART 与 CAN：节拍和接口都要对

    约 25 分钟实战上机 + 仿真双路线

    串口偶尔一个字节变乱码，重新发送又好了；你怀疑线坏了，却不知道如何拿到证据。UART 没有单独时钟线，接收方靠自己的节拍猜采样时刻，所以帧尾特别值得检查。

    先建立一个能用的理解

    UART（通用异步收发器）采用异步串行收发方式，像两人约好语速后通过一根线说话。空闲通常为高，起始位拉低，数据位通常最低位先发，随后可有校验位，最后停止位为高。

    波特率是每秒符号数；常见二进制 UART 一个符号承载一位，因此数值通常等于 bit/s。校验位检查一帧里 1 的个数是奇数还是偶数，像简单点名；它不能修复错误，也不能检测所有错误组合。

    8N1 表示 8 数据位、无校验、1 停止位；8E1 表示 8 数据位、偶校验、1 停止位。不要把软件示例的校验设置直接照搬到目标设备。

    接收器在起始沿重新对时，随后按自己的位周期采样。发送端和接收端速率有差异时，采样点会在一帧内逐步偏离中心；每一帧重新同步，误差不是无限跨帧累计。

    3% 不是通用的必坏界线。理想短帧可能仍正确；较长帧、起始检测误差、慢边沿、抖动和噪声会共同吃掉裕量。本演示先让接收端相对标称值快 3%，再让发送端慢 2%，两端相对误差约为 +5.10%；这说明只看一端的“3%”不能判断整体裕量。真实设备还要加上起始检测、抖动和噪声等误差。

    TTL/CMOS UART是低压逻辑侧信号；RS-232可能有正负电压且逻辑极性不同；RS-485使用差分线对。它们可能承载 UART 帧，却不是相同电气接口。应在合适收发器的逻辑侧测量，不能直接把小盒子接到 RS-232 或差分总线。

    总线位置 适合这个分析仪的接点 需要注意
    低压 UART 兼容电平的 TX/RX 与 GND TX/RX 标签按设备方向核对
    RS-232 RS-232 收发器的 MCU 逻辑侧 总线侧可能为负电压，不能直接接
    RS-485 RS-485 收发器的 RO/DI 逻辑侧 差分电压与共模范围不能用普通单端输入代替
    CAN CAN 收发器的 RXD/TXD 逻辑侧 CAN_H/CAN_L 需合适差分探头或收发器

    CAN（控制器局域网）用 CAN_H/CAN_L 的差分物理层抵抗共模干扰，收发器负责把它转换成 MCU 逻辑信号。经典 CAN 的仲裁像多人同时报号码，显性位会覆盖隐性位；发隐性却读到显性的节点退出竞争。经典 CAN 从帧开始到 CRC 序列的规定区域内，连续五个同极性位后插入相反位，接收端去填充；CAN FD 的规则还有区别。本章只建立概念，解码须匹配实际协议、速率与设备能力。

    9. 信号完整性：漂亮方波背后的盲区

    约 15 分钟进阶上机 + 仿真双路线

    解码一切正常，换长一点的线却突然失灵。这不是软件在捉弄你：数字记录只保留“过了门限没有”，把电压离危险边缘有多近这件事藏起来了。

    先建立一个能用的理解

    信号完整性关心信号到达接收端时，电压形状和时间是否仍足够可靠，像快递不仅要送达，还要没有破损。过冲、振铃、慢上升与噪声都可能缩小可用的判断窗口。

    过冲是边沿超过目标电压，振铃是边沿后往复摆动，像弹簧到位后还在抖。只要它们没改变逻辑判断，分析仪就可能画出完全干净的方波。

    抖动是边沿时刻在来回变化，像每次拍手都早晚一点；毛刺是短暂的非预期脉冲，像说话时插入一个很短的音。能否抓到它取决于宽度、采样间隔与输入响应。

    电平裕量是实际电压离不可靠区还有多远，像汽车离路边还有多少余量。分析仪门限与目标芯片门限不同，可能出现“分析仪解对了，芯片却读错”的情况。

    阈值演示使用的是来自 3.3 V 系统、但被噪声与衰减破坏的波形：低电平上的噪声可能超过 0.8 V，某些受损高脉冲可能达不到 2.5 V。正常、已稳定到 3.3 V 的高电平不会仅因把门限调到 2.5 V 就凭空消失。

    探头负载是探测本身增加的电容与电阻，像在细绳上挂了一个小夹子，也会影响绳子动作。长地线还增加回路电感，可能造成或放大振铃；高速信号尤其需要短接地和合适探头。

    正确顺序是：先用示波器在接收端确认波形质量、实际电平与裕量，再用逻辑分析仪查看多路时序和协议。遇到偶发问题，两种工具围绕同一个事件标记抓取。不要在教程里把软件阈值滑块当成所有实物都有的旋钮。

    10. 高级技巧：把多份记录连成证据

    约 20 分钟进阶上机 + 仿真双路线

    你已经能看串行协议，但复杂故障会跨越几个信号，或一天只发生一次。高级技巧的目标不是堆工具，而是让不同记录能围绕同一个问题互相证明。

    先建立一个能用的理解

    并行总线把多位数据放在多根线上，像几个人并排举牌。必须知道哪根是最低位、何时数据有效、哪个控制信号表示读或写；仅把几条波形拼成数字还不够。

    8 通道预算要先分配。例如 4 位数据 + 时钟 + 片选 + 读写 + 事件标记已经用满。更宽地址和数据不能在同一次采集中凭空补齐；减少观察范围、用固件标记或借更多通道的设备。

    流式采集边采边传到电脑，像边录边写硬盘；缓冲采集先存进设备内存再传出，像先装满相机卡。常见 FX2 方案偏向 USB 流式传输，持续能力受 USB、驱动、电脑内存/磁盘和软件限制。

    CSV是便于表格或脚本读取的文本数据；VCD是常用的数字信号变化记录格式。导出前要确认单位、通道名和表示方式：逐采样表与只写变化事件的表，大小与解读方法不同。

    自定义解码器让你按私有协议规则解析边沿，像给方言写一份字典。sigrok 的协议解码器通常用 Python 实现；先定义帧起点、位序、校验、错误恢复和测试样本，再写代码，避免让解码器迎合某一次记录。

    联合调试时，最可靠的线索是同一个物理标记边沿。两台仪器分别记录这个边沿，之后对齐比较；它们没有共同采样时钟时仍可能有时间偏移和漂移，不能假定所有位置都精确同步。

    真实操作：一步一步做

    1. 先列通道预算和信号表，写明每条线的方向、位权、有效电平和采样条件。对并行数据，至少保留能说明“何时有效”的控制线。
    2. 为偶发事件选记录方案：低占空比问题可降低不必要的通道数或使用合适事件捕获；高速细节不能靠无条件降采样率保留。
    3. 在 PulseView 保存原始会话，再通过导出功能选择实际支持的格式；若当前构建没有目标格式，使用匹配的 sigrok-cli 输出模块或离线转换。
    4. 导出一个很小的已知样本，核对时间单位、逻辑值、通道顺序与文件头，再处理长记录。CSV 数字列不要让表格软件擅自改变单位。
    5. 私有协议先人工标注几个正确帧与错误帧，再实现解析并比对。测试应覆盖截断帧、错误校验、丢边沿与重新同步。
    6. 与示波器联调时确认两个仪器的地和输入都安全兼容，把标记边沿保留在两份数据中，并记录各自采样率与触发偏移。

    11. 完整排障：三个问题，三个闭环

    约 30 分钟综合上机 + 仿真双路线

    排障不是看到一个异常就换一颗芯片。先提出可证伪的假设，再用波形找到最早分叉，做最小修改，最后复测。下面三个案例是教学构造，字节和时间均为示例值，不能代替具体器件手册。

    先建立一个能用的理解

    闭环验证意味着你的解释能预测修改后的行为，并且记录证明预测发生了。像修漏水：不仅擦干地板，还要找到漏点、处理漏点，再开水确认不漏。

    每个案例都保留两类证据：原始电平与时间，以及解码器的解释。先看接线、电平与时序，再看字节意义；不让某个“像答案”的解码结果替你下结论。

    I²C：地址有 ACK，温湿度数据却全是 0xFF

    1. 现象：访问地址成功，但应用显示异常数值；解码气泡中的数据为 FF。
    2. 假设：目标尚未完成测量；寄存器指针或命令未初始化；上拉过大与总线电容使上升太慢。这三条需要不同证据。
    3. 接线与设置：SDA、SCL、GND；示例 100 kHz 总线用 2 MS/s 抓完整命令和等待过程，同时保留前后事务。
    4. 抓到的波形：写地址 ACK 后立刻改为读，没有器件手册要求的测量等待；SDA 在数据八拍持续高。ACK 只能证明该地址阶段有人应答，不证明数据有效。
    5. 判读结论：先核对器件协议。教学情景中，命令与指针正确，模拟上升时间合格，但读取早于数据就绪。
    6. 怎么改：按器件手册等待完成或检查就绪状态，保留必要的指针写入与重复 START。若真实记录显示慢上升，另按上拉与总线电容整改，不能用等待时间掩盖电气问题。
    7. 复测验证：在相同采样条件下抓取命令、等待、读数据全流程，确认有效数据与应用换算一致；连续重复并测试温度/供电允许范围内的条件。

    替代分支：若缺少指针写入，补齐手册要求后复测；若示波器证实上升过慢，计算并调整上拉或降低负载。不能仅凭 FF 在三条假设中任选一个。

    SPI Flash：读取 ID 得到 0xFF 0xFF

    1. 现象：初始化失败，ID 返回全 FF；目标具体 ID 必须查器件资料，不能把某个厂商的三字节 ID 当通用值。
    2. 假设：CPOL/CPHA 与器件不匹配；CS 在命令和响应之间提前释放；MISO 接错或器件未被使能。
    3. 接线与设置：SCLK、MOSI、MISO、CS、GND；先把时钟降到安全示例 1 MHz，以示例 10 MS/s 抓完整事务，设置手册要求的模式。
    4. 抓到的波形：MOSI 发出示例读取 ID 命令 0x9F 后，CS 短暂回高；后续时钟位于新的片选窗口，MISO 一直被读为高。
    5. 判读结论：在这个教学记录里，最早异常是 CS 中断了事务。先证明它，再核对模式；全 FF 本身不是模式错误的专属证据。
    6. 怎么改：让驱动在命令与响应期间保持 CS 有效，并满足建立/保持时间；按器件支持的模式配置主机和解码器。
    7. 复测验证：同一 CS 窗口内出现命令与响应，MISO 在有效采样沿具有稳定值，ID 与该芯片手册一致；提高到目标时钟后再次验证。

    替代分支：若 CS 正确而字节错位，逐位检查采样边沿与首位准备时间。只修改解码器不能修复 MCU 已经发错的时序。

    UART：长时间偶发乱码，终于抓到停止位错误

    1. 现象：多数文本正常，偶发 framing error；短记录很难覆盖出错时刻。
    2. 假设：双方实际波特率不匹配；慢边沿或噪声侵蚀采样裕量；帧格式不同或数据丢失。
    3. 接线与设置：观察逻辑侧 TX/RX 与错误标记 GPIO，为与本页动画对照，使用示例标称 9600 bit/s、8E1 和 1 MS/s 采样，实际值仍按你的设备配置。具备能力的仪器可设置“前导字节后等待返回、超时或帧错误”序列条件。
    4. 基础设备替代：在接收程序检测到错误时翻转标记 GPIO，使用可用边沿触发并保留上下文；或进行较长记录后按错误注释和时间间隔筛选。普通 FX2 不凭空拥有协议序列触发。
    5. 抓到的波形：首位采样接近中心，后续采样点逐步靠近边界；本例接收端比标称快 3%、发送端比标称慢 2%，相对误差约 +5.10%；停止位采样提前落在值为 0 的偶校验位，报告 framing error。
    6. 判读结论：不是“发送够久误差跨帧累积”，而是每帧内部的定时偏差造成帧尾采样错位；真实板子还要检查噪声与边沿是否进一步侵蚀裕量。示波器记录用于排除或确认这部分影响。
    7. 怎么改：核对外设时钟源、分频和实际波特率，必要时采用更准确时钟；同时修正受损线路与电平转换。
    8. 复测验证：重测位时间与停止位采样裕量，在原数据量和运行条件下重复长记录，错误计数与波形共同验证修复。

    真实操作：一步一步做

    1. 为当前故障写出三个最可能原因，每个原因配一个“如果成立，波形会怎样”的预测。
    2. 画接线表，写采样率、深度、触发、解码配置，保存失败记录。
    3. 定位成功与失败的首次分叉；若是模拟质量问题，补充示波器证据。
    4. 每次只做一个主要修改，并预测修改后的具体波形变化。
    5. 用相同条件复测，再在实际目标速度与运行负载下检查持续可靠性。

    I²C 地址 ACK 能证明读出的数据一定有效吗？

    不能。它只说明该应答时隙被拉低；还要检查命令、寄存器指针、就绪状态和实际数据阶段。

    SPI 全 FF 后，为什么先看 CS 和 MISO？

    它们能快速判断器件是否被选中、是否真的驱动返回数据；全 FF 不足以单独证明模式错误。

    UART 误差会在几千帧之间一直累加吗？

    正常接收会在每帧起始沿重新同步。需要分析的是单帧内部的采样偏移，以及系统长期运行时的温漂、噪声或其他条件变化。

    12. 十大误判急救包：带着证据排查

    约 15 分钟随查随用上机 + 仿真双路线

    遇到问题时，你需要一张能立即执行的检查路线，而不是再读一遍整本书。先匹配症状，再验证最可能的三个原因；每一步都保留一个可以观察的结果。

    先建立一个能用的理解

    急救表按“症状 → 三个可能原因 → 排查步骤”排列。它是定位入口，不是自动诊断。若某条检查不能解释原始波形，就回到上一层重新核对假设。

    每次求助前准备四样东西：接线图、设备与电平信息、完整采集设置、包含故障前后的原始记录。别人才能帮你复核，而不是对着一张没有时间尺的截图猜。

    症状 最可能的 3 个原因 排查步骤
    ① 波形乱跳 未共地；探针悬空/接触不良；电平与门限不兼容 先断电核对 GND 和接点 → 查输入范围 → 抓已知方波确认基线
    ② 解码乱码 通道映射错误；波特率/模式/位序错误；采样率或电平判定不合适 先看原始波形 → 手数一字节 → 一次只修正一个解码参数
    ③ 抓不到毛刺 采样间隔太大；窗口或触发未覆盖；输入带宽/毛刺响应有限 计算采样间隔 → 高采样率重复抓 → 用合适示波器或更强仪器验证
    ④ 只能抓约 1 秒 样本数限制；采样率偏高；软件/主机传输与内存限制 用深度÷采样率核算 → 查看实际限制 → 按所需细节调整记录方案
    ⑤ 通道不够 信号预算未分优先级；地址数据同时太宽；无有用事件标记 先保留时钟/片选/关键数据 → 加固件标记 → 借更多通道设备
    ⑥ 电平不匹配或通道受损 超过输入额定值；负电压或未知参考；错误接电源或短路 立即断开并检查 → 核对资料与实物 → 用合适转换/保护后再测，受损设备隔离报修
    ⑦ I²C 无 ACK 地址/方向表示混淆；器件未供电或未就绪；上拉/接线/电平异常 数第九拍 → 核对 7 位地址和供电时序 → 查 SDA/SCL 与模拟上升沿
    ⑧ SPI 全 0xFF MISO 未被驱动；CS/命令事务错误；模式/位序或通道映射错误 先看原始 MISO → 圈完整 CS 窗口 → 按手册逐位核对
    ⑨ CAN 抓不到 没有通过收发器取逻辑侧；通道/极性/速率错误；采样能力或帧类型不匹配 定位 RXD/TXD → 核对逻辑电平和速率 → 检查经典 CAN / CAN FD 与仪器能力
    ⑩ 看着正常却仍失败 模拟裕量不足；关心事件在窗口之外；分析仪与芯片门限/采样点不同 示波器查接收端质量 → 扩展上下文 → 对比目标接收条件并复测

    真实操作：一步一步做

    1. 先选最接近的症状，抄下对应三条原因，不急着修改电路。
    2. 按表中顺序检查，记录每条原因被支持还是被排除，以及证据来自哪里。
    3. 优先确认供电、电平和共地，再处理采样，最后修正解码与协议流程。
    4. 修改之后回到原场景复测；如果换了速度或数据内容，明确写出变化，避免混淆条件。
    5. 问题解决后保存一段健康参考波形，下次同类故障可直接比较。
